capy.

A music CLI that lives in your terminal. Search, control playback, and sync your Spotify and Apple Music playlists to your own Google Drive.

$ go install github.com/Tai-ch0802/capy-music/cmd/capy@latest
  • macOS
  • Windows
  • All credentials are your own
  • 中文版

Getting started

Three steps, from the bottom up: first let capy reach your music platforms, then decide whether to sync your playlists to the cloud. capy's interface is in English by default; capy config set language zh-TW switches it to Traditional Chinese.

Create your own Spotify app

capy doesn't hold anyone's credentials, so the Spotify half uses your own app. Create one in the Spotify Developer Dashboard and set its redirect URI to http://127.0.0.1:8888/callback. It has to be 127.0.0.1: Spotify rejects localhost.

$ capy auth login spotify
# the wizard asks for the client ID, then opens the browser to finish authorization

Try your first command

You can start right away, with no other setup. Search prints its results directly: an aligned table in a terminal, clean TSV in a pipeline.

$ capy search Yellow
$ capy play Coldplay       # an artist: plays their top tracks
$ capy now                 # what's playing

Google is only needed to sync playlists

The master copies of your playlists live in the application data folder of your own Google Drive (only capy can see it, and you can clear it at any time). Only this step needs a Google login, and it asks for just three permissions: your identity, your email address, and the application data folder.

$ capy auth login google
$ capy pl link Commute spotify:Commute   # link a platform playlist
$ capy pl sync Commute                   # two-way sync

Interactive mode

Type capy in a terminal, with no arguments. The capybara at the start twitches its ears, blinks, eats the grass in its mouth down to a stub and picks up a new stalk. If the terminal is big enough (at least 30 rows tall), it stays at the bottom of the screen and goes on with its day: it blinks and flicks an ear now and then, and every so often eats a stalk of grass. When you type / to open the menu it makes room, and it steps aside while a command runs. In a smaller terminal it freezes after about three seconds (press any key to skip), and after that only the bottom four lines of the screen change. If you don't want any animation, set CAPY_MOTION=never: it freezes right away and never moves again. Either way, everything above is the terminal's own scrollback: the commands you typed, their output and any errors stay there, and you can scroll back and copy them. In a pipeline or cron it still only prints the help; it never turns into a program waiting for a key press.

Press / to open the command menu: it filters as you type, and Tab or ⏎ puts the command on the input line so you can add arguments. Once you've typed a full command (for example /pl show Commute), the menu closes and ⏎ runs it; the leading / is dropped automatically. The menu grows upward, over the scrollback, and never gets mixed into your history. The list is generated from the command tree itself, not kept as a separate copy.

A command typed on that line runs capy itself again, not inside the same process. So every subcommand keeps its usual behavior: tables where there are tables, and a confirmation question wherever it would ask one. Put playlist names that contain spaces in double quotes, for example pl show "Road Trip".

When the playback state can't be read, the full error is printed into the scrollback and stays there, and the line at the bottom keeps only a short version; after five failures in a row polling stops, and r reconnects. The command line works no matter what: when capy can't connect is exactly when you need it most (doctor, auth login).

Web UI

capy --web starts a web UI on this computer, bound to 127.0.0.1 only. At startup it prints a URL with a one-time token, and in a terminal it also opens your browser for you (in a pipeline or in the background it only prints the URL).

It opens on Move: move a playlist from one platform to another in three steps. Choose the source and the destination (you can see at a glance whether each platform is connected, and connect one on the spot) → pick a playlist and decide whether to create a new one or add to an existing one → review which songs will move; nothing is written until you confirm. Matching the songs shows real progress, and songs that can't be moved are listed one by one. It never deletes the source, only adds, and keeps the order; it's free and has no song limit, because it runs on your own computer with your own accounts.

The limits first: moving into the Local library can only add to an existing M3U file (Spotify and Apple Music can create new playlists); whether songs moved into Apple Music are also added to your Apple Music library depends on your Apple Music settings, and they can only be moved into playlists you created yourself; connecting your accounts the first time takes a few minutes (Spotify needs your own app, and for Apple you copy the token yourself), and in exchange nobody holds your credentials for you. M3U playlists on your disk can be moved to Spotify too.

The other pages: My playlists, Sync, Search and Accounts; under Advanced are Console (type any subcommand, just like in the terminal), ISRC lookup (asks all three platforms at once) and Diagnostics. The now-playing bar is always at the bottom of every page: what's playing, progress and playback controls, everything capy now shows. Every action on the page is a capy command behind the scenes, and Console keeps the full record; anything that needs your confirmation is asked by the command itself, and the page never answers for you. The Language menu in the navigation switches the interface language: it runs capy config set language, the same setting the terminal uses (so the terminal switches too), and the page reloads once the change is saved.

The web UI stays on your computer: it binds to 127.0.0.1 only, so other devices on your network can't reach it; a one-time token is generated at every start, and the URL stops working when the process exits. Credentials never pass through the page: a secret you type into a wizard only goes from the browser into the process and then into the keychain, and token values in command echoes are always masked as ***.

It runs one command at a time (a second one is refused), because it shares the same Drive and local data as the terminal. While a command runs, a status line appears at the bottom: what it's doing, how long it has been running and the latest line it printed (while matching songs, which song it's on); the Stop button next to it stops it at any time (so does Ctrl-C on Console's command line). Once you've confirmed a write, Stop asks you to press it a second time, because stopping halfway may leave only part of the change written. A few commands aren't available on the web: the debug group, --auto, the three secret flags (use the wizard instead) and now --watch (the now-playing bar already shows it); capy update runs, but the web process is still the old version afterwards and asks you to restart it.

The terminal's interactive mode runs capy itself again, so each subcommand keeps its usual behavior; the web UI runs commands inside the same process, and the page answers their prompts. The two work differently because a terminal already has a TTY it can hand to a child process, and a browser doesn't.

What it can do

Grouped by topic below. In a terminal, each command prints a table meant for people (cells wrap instead of being cut off when they don't fit, and IDs are always complete; when the table is wider than the terminal, a pager opens first: one row per line, ← → scroll sideways, ↑ ↓ up and down, g G jump to the top and bottom, q leaves, and Ctrl-C stops the whole command; after you leave, the table stays in the scrollback, wrapped. Commands run with --yes don't open the pager, and CAPY_PAGER=never turns it off entirely). In a pipeline the output is TSV, ready for cut and awk.

Search and playback

  • capy search <query>Searches for tracks. --provider apple switches the platform, and --limit sets how many results you get.
  • capy play <query>One entry point for tracks, an artist's top tracks and your own playlists. When several things match, a terminal opens a picker; a script gets exit code 2 and the list of candidates. capy never just picks one and plays it.
  • capy play artist:ColdplayA prefix sets the type: artist:, pl: or track:, the same as --type.
  • capy pause / next / prevBasic remote control.
  • capy seek 1:23Jumps to a position in the track. Use 1:05:30 for longer content, or plain seconds such as 83 in scripts.
  • capy vol 40Volume from 0 to 100. Phones and some speakers don't allow remote volume changes; capy then says plainly that the device refused.
  • capy nowWhat's playing. --watch keeps it updated, with a progress bar.
  • capy devicesLists the devices that can play, for use with play --device.

Playlists

  • capy pl listLists the playlists on a platform.
  • capy pl show <name>Shows a playlist's tracks.
  • capy pl link <name> <platform>:<playlist>Links a playlist on a platform to capy's master copy. Only the links you make explicitly count; capy never guesses from playlists that share a name.
  • capy pl link <name> spotify --createCreates an empty private playlist with the master copy's name on Spotify or Apple Music (apple --create) and links it right away. Use it when you copy a playlist over from another platform, so you don't have to create it in the app first. If you already have a playlist of your own with that name on the platform, it stops and tells you how to link that one instead.
  • capy pl pullBrings a platform's changes into the master copy. It lists what will change first and writes only after you confirm.
  • capy pl pushThe other direction: from the master copy back to the platform. This device must have pulled before, and the platform must have no changes that haven't been pulled yet.
  • capy pl syncPull, then push: one table, one confirmation. This is the one to use day to day.
  • capy pl dedup <name>Removes duplicate tracks from the master copy: the same platform id or the same ISRC counts as one track. The first copy is kept and the rest stay in order, then the result is pushed to the platforms capy can write to; if there are no duplicates, nothing is written. capy pl dedup apple:Workout instead reads the platform playlist directly and only prints a report (it doesn't touch Drive and needs no link); to have capy remove the duplicates, link the playlist to a master copy and use the first form.
  • capy pl unlink <name> <platform>Removes the link; the master copy's content stays as it is.

Run these commands without a playlist name in a terminal and a picker opens: pl link asks three times (the platform → which playlist on that platform, where Spotify and Apple Music also offer "create a new empty playlist" → which master copy to link it to, where you can also create a new one on the spot), and pl unlink asks twice. Behind a pipeline or in cron it doesn't ask, and you still have to give every argument.

Cross-platform mapping

  • capy resolveMaps the tracks in your master copies to their ids on each platform. It tries an exact ISRC match first and fuzzy matching only when that fails, and writes a mapping automatically only when the score is high enough.
  • capy resolve --reviewThe matches that didn't score high enough wait in a queue, and you review them one by one in a terminal.
  • capy resolve pin <cid> <platform>:<id>Pins a mapping by hand, for scripts. Pinning none means the platform doesn't have this track.

Settings and maintenance

  • capy auth login / status / logoutAuthorization for each of the three platforms. Credentials only go into your operating system's keychain, never into the config file or Drive.
  • capy doctorOne-stop diagnostics: what's wrong with your settings, credentials and connections, each with a next step you can follow.
  • capy config get / set / listNon-secret settings, such as the default platform, the local library folder and the interface language (language): the interface is in English by default, capy config set language zh-TW switches it to Traditional Chinese, and en switches it back.
  • capy exportPrints the master copies cached on this computer to standard output, exactly as they are. It touches neither the network nor the keychain.
  • capy updateUpdates capy itself.
  • capy completion <shell>Generates shell completion.

Copy a playlist to another platform

One command does it. The example copies the Apple Music playlist "Roadtrip" to Spotify; you need to be logged in to Spotify, Apple Music and Google first.

$ capy migrate Roadtrip --from apple --to spotify           # create a private playlist with the same name on Spotify and move the tracks over
$ capy migrate Roadtrip --from apple --to spotify:Driving   # or add to an existing playlist, after the tracks it already has
$ capy migrate Roadtrip --from spotify --to apple           # the other way: create a playlist with the same name on Apple Music and move the Spotify tracks over
$ capy migrate                                             # no arguments: pick the source, the playlist and the target step by step

It lists what it will move first and does nothing until you confirm; when a new playlist is needed, that too is created only after you confirm. The target's existing order comes first, and the source's tracks follow in the source's order; tracks the target already has (the same track, or the same ISRC) are skipped. The source is never touched, and the target only gets additions: if the target has removals, reorders or renames that haven't been synced, it stops and asks you to run capy pl sync first. Tracks that weren't found on the target platform aren't pushed this time; in a terminal you can review them one by one on the spot, otherwise the last lines give you the commands to add them later. Afterwards only the target is linked to the master copy (the source isn't linked: it's a one-time copy); if you want to follow the source's changes later, the last lines also give you the pl link and pl sync commands. The exception: if the master copy is already linked to the source (you were halfway through the manual steps below), the source side is pulled into the master copy too, the master copy wins, and the last lines say that both sides are linked. Whether tracks moved into Apple Music are also added to your Apple Music library depends on your Apple Music settings (that's Apple's behavior), and they can only be moved into playlists you created yourself.

What happens behind the scenes: capy links both platforms to the same master copy, then pushes. If you want the two sides to stay in sync, do it by hand once as shown below; after that, capy pl sync is all you need.

Link both sides to the same master copy

Link the Apple playlist first; the master copy is created automatically if it doesn't exist. Then use --create to create an empty private playlist with the same name on Spotify, linked to the same master copy.

$ capy pl link Roadtrip apple:Roadtrip
$ capy pl link Roadtrip spotify --create

Pull both sides once

Leave out --provider: on the Apple side the tracks are pulled into the master copy; the Spotify side is empty, so this device only records what it looked like. Without this step, the push later on is refused.

$ capy pl pull Roadtrip

Find each track on Spotify

Tracks with an ISRC are matched exactly; the rest are fuzzy-matched on title, artist and duration, and the ones that don't score high enough go into a queue for you to review.

$ capy resolve Roadtrip --provider spotify
$ capy resolve --review        # only needed if the previous step listed a queue

Look first, then push

The skip rows in the table are the tracks that can't be copied this time: tracks not yet matched on Spotify, usually ones you uploaded to Apple yourself or ones Spotify simply doesn't have.

$ capy pl push Roadtrip --provider spotify --dry-run
$ capy pl push Roadtrip --provider spotify

Nothing gets deleted along the way: this is the Spotify side's first pull, so everything pushed is an addition. Afterwards the two sides stay linked, and whenever either side changes, capy pl sync Roadtrip carries it across. If you only want a one-time copy, use capy migrate above, or run capy pl unlink Roadtrip apple when you're done. The other direction (Spotify to Apple) works the same way: capy migrate Roadtrip --from spotify --to apple, or swap the two platforms in the steps above (capy pl link Roadtrip apple --create).

Writing to Spotify hasn't been verified on a real account yet

Creating playlists and pushing tracks were implemented from Spotify's official documentation as of February 2026, but haven't been run against a real account yet. If you get a 404, or a playlist capy created shows up as public in the app, please report it.

Local library

M3U files on your disk can act as a platform too, with two-way sync with Spotify. They're tied to this computer: on another computer, capy skips this link instead of treating the playlist as deleted.

$ capy config set local_root ~/Music/playlists
$ capy pl link Commute local:Commute.m3u8
$ capy pl sync Commute

Track metadata lives in library.json in the same folder, and you maintain it yourself. Only tracks with an ISRC filled in can be matched automatically with the same track on a streaming platform; the others each stay a separate track. Writing back rewrites the whole file, so comments and #EXTINF lines that other tools wrote into the M3U are overwritten.

Good to know

Your master copies are in your own Drive

Not on our servers, because there are none. The SQLite database on this computer is only a cache: delete it and the next run rebuilds it completely from Drive.

Removals are always shown first

Anything that would remove tracks from a playlist lists them first for you to confirm, and above a threshold it stops outright; only --force lets it through. --dry-run only shows, and changes nothing.

Playlist order is your memory

No path in capy sorts or shuffles a playlist: sync only follows a new order when the platform itself reordered the playlist, dedup only removes the later copy, and the tracks that weren't touched never change their relative order.

The Apple Music token is one you copy from the web

That isn't a use Apple officially supports: the token expires, the method may stop working at any time, and you use it at your own risk. capy only guides you through copying it; it never reads your browser's cookies and never injects any script.

Apple Music can be written to, but only playlists you created

Adding tracks uses Apple's documented endpoint; removing, reordering and renaming use the endpoints Apple's own web player uses, which Apple has made no promises about, so they'll break if Apple changes them. Apple-curated playlists, Favorite Songs and Purchased Music can't be written: capy stops and writes nothing. capy doesn't write collaborative playlists at all for now (Apple returns a 500 error when their contents are replaced), and sync skips such a playlist and says why; copying it into a regular playlist first and linking that one usually works (not tested). Whether tracks added to a playlist are also added to your Apple Music library depends on your settings in Apple Music; that's Apple's behavior. Removing and reordering replace the whole track list: the playlist order always follows the master copy, and whether the Date Added shown in the Mac Music app gets reset hasn't been verified.

Every command works in a pipeline

When it isn't in a terminal, output is always plain-text TSV, with no colors and no interactive prompts. Exit codes mean something: 0 success, 1 error, 2 needs you, 3 stopped by a safety check. In the TSV of pl pull / push / sync, migrate, dedup and resolve, the reason column is for people and follows the interface language; scripts should read the last column, reason_code, which is the same in every language.
