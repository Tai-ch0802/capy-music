# 多語系(i18n):預設英文、可切繁中、預留更多語系(2026-09-23 研究與計畫)

使用者:「現在是時候來支援英文語系了。調整成預設為英文,可以在 cli 的 config 裡頭去設定為繁體中文、也可以在 web 上去做設定。
因為是開源專案,在未來可以支援更多語系。所以務必規劃好類似 i18n 的語系切換模板。你先研究整理一下 plan,我看完確認我們認知一致以後再進入開發。」

**T1 實作後的調整(2026-09-23;回應 #85 review 與實作查證,內文已一併改好):**
1. 搬字串期間 production 預設**維持 zh-TW**,清空 CJK 白名單的那個 PR 才改成 `en`(守門測試強制)。否則 T1 到 T2d 之間 main 上的 dev binary 會半中半英。

### 0.2 已經不用動的

- 機器用的 TSV 欄名本來就是英文大寫(`ACTION`、`DIR`、`CID`…),`action` / `dir` 的值(`add`、`skip`、`pull`、`push`…)與 exit code 也是英文或數字。
- cobra 自己的說明標題(`Usage:`、`Flags:`)現在就是英文。
- 程式碼註解、ARCHITECTURE 與計畫文件是給開發者看的,維持中文。
- `golang.org/x/text` 已經是直接依賴(local 的 NFC / NFD),它的 `language`(BCP 47 語言代碼)與 `feature/plural`(CLDR 複數規則)可以直接用,**不必加任何新依賴**。

### 0.3 會壞掉、必須先處理的地方

- **網頁介面有五處靠比對中文文字判斷 CLI 的輸出**,預設改英文後都會失效:
  1. 帳號頁用正規表示式解析 `auth status` 的中文輸出(`有效至`、`keychain 存在`、`已於 … 過期`)。
  2. 搬家精靈比對 migrate 的提示標題「現在逐筆裁決?」。
  3. 搬家精靈用原因欄開頭「推到 」判斷一首歌推不推得過去;migrate 列本身沒有機器可讀的欄位分辨這件事。
  4. 搬家精靈用表頭「名稱」「曲數」找欄位,表格元件用「時長」決定要不要格式化成分秒。
  5. 主控台用「已取消」藏掉取消時重複的錯誤訊息。
  另外兩個下拉選單拿顯示文字「(預設)」「(全部)」當值。
- **四張表的表頭是中文**:`config list`、`devices`、`pl list`、`pl show` / `search`。其他表(pull、push、sync、resolve、dedup)是英文大寫欄名。
- **29 個 package 層級的錯誤值**(`ErrAuthExpired`、`ErrNotFound`、Apple 的 `ErrNotRunning`…;研究時估約 18 個,T1 實數)在程式啟動時就把中文訊息算好了,切語系不會跟著變。
- **有些給人看的文字是讀完資料就算好、存在欄位裡的**:`PlaylistRef.Unwritable`(Apple 清單寫不了的原因)、`canon` 的變更原因與略過原因、限流錯誤的訊息。研究時以為它們也要改成「印出時才翻」;**T1 查證:這些欄位都在同一個命令內算好、印出**,沒有存進 Drive 或 SQLite,語系在命令開始前就定了,所以照一般字串搬即可。真正要延後翻的只有 package 層級的值(init 比語系設定早)。平台自己回傳的錯誤文字(Spotify、Drive 的 `reason` / `message`)是原文,不翻。
- **語系要在建命令樹之前決定**:cobra 的 `Short` / `Long` / flag 說明是建樹時寫進去的。`Execute()` 是入口;網頁每個 job 也會重建一次命令樹(`web_run.go` 已經在這個時機 `resetDefaultProvider()`),正好沿用。但 `/api/commands` 的命令說明是伺服器啟動時算一次;「命令樹只在啟動前建一次」又是網頁模式 -race 不變式的一部分,所以不能靠重建命令樹來換語言。
- 網頁頁面寫死 `<html lang="zh-Hant">`。

## 1. 目標與這一輪不做的事

**目標**

- 預設英文。`capy config set language zh-TW` 切到繁體中文;網頁介面有語言選單,改的是**同一個設定**,兩邊互通。
- CLI 的說明、錯誤訊息、提示、表格、互動式介面、網頁介面,全部走同一套語系目錄。
- **新增一個語系 = 新增一個檔案**:複製英文目錄、翻譯、在支援清單加一行;漏翻的地方測試會列出來。

**這一輪不做**

- 自動偵測作業系統語系。你要的是「預設英文」,自動偵測會讓中文系統的使用者一開始就是中文;之後想要再加。
- 環境變數覆寫(例如 `CAPY_LANG`):設定檔就夠了,多一個入口反而會讓「網頁切了卻沒反應」。
- 翻譯程式碼註解與開發文件。
- 開發者工具(`cmd/spotify-probe`、`capy debug` 群組、測試用的假伺服器):不進語系目錄,只把中文改成英文。

## 2. 設計

### 2.1 語系目錄的格式(給新語系用的模板)

- 每個語系一個 JSON 檔:`internal/i18n/locales/en.json`(來源,也是新語系的模板)、`zh-TW.json`。JSON 是標準函式庫就能讀的格式,Weblate、Crowdin 這類翻譯平台也都支援。
- 扁平的「key → 字串」。key 用點分命名空間,依功能區分,例如 `cmd.migrate.short`、`migrate.err.target_not_editable`、`web.move.title`。
- **具名佔位符** `{playlist}`、`{count}`:不同語言的語序不同,譯者自己決定位置,不必管參數順序。
- **複數**:值可以是物件,依 `count` 選 CLDR 類別。中文只需要 `other`,英文要 `one` 與 `other`;將來的俄文、阿拉伯文也照各自的規則。
- 多段的 `Long` 說明用 `\n` 換行。英文版不必逐字翻譯中文,寫成道地、精簡的英文。

```json
{
  "migrate.done": {
    "one": "Moved {count} track from {src} to {dst}",
    "other": "Moved {count} tracks from {src} to {dst}"
  },
  "apple.err.not_editable": "Apple only lets you edit playlists you created; \"{name}\" ({id}) is not one of them"
}
```

### 2.2 程式介面(`internal/i18n`,預估一兩百行,不加依賴)

- **`internal/i18n` 是只依賴標準函式庫與 `x/text` 的葉子套件。** 它不讀 config,只負責「目前是哪個語系」與翻譯。讀 config、決定語系的是 cli 那一層。這樣 `auth`、`provider`、`canon` 這些低層套件才能用它,不會跟 `config` / `cli` 繞成循環依賴;這也是新語系能「只加一個檔」的前提。

- `i18n.T(key, "name", v, …)` 回傳字串。目前語系缺這個 key 就退回英文,英文也缺就回 key 本身,測試會抓到。
- `i18n.Errorf(key, "err", err, …)`:佔位符 `{err}` 放被包起來的錯誤,保留 `errors.Is` / `errors.As` 的行為。訊息在 `Error()` 被呼叫時才翻,所以也拿來取代 package 層級的錯誤值(`i18n.Errorf(key)`,回傳指標,`errors.Is` 比的是同一個值)。原計畫的 `NewError` 併進它;`Msg` 不做,理由見 §0.3。
- `i18n.Set(tag)` / `i18n.Current()` 用 atomic 存目前語系;`i18n.Supported()` 回傳支援清單。
- **規定 key 必須寫成字串字面**,不能在執行時拼出來,這樣測試才能靜態檢查每個 key(見 §2.5)。

### 2.3 語系怎麼決定

- config 新增 `language` 欄位,可設 `en` / `zh-TW`;沒設 = `i18n.Default()`。預設在 T2 搬完之前維持 zh-TW,清空 CJK 白名單的那個 PR 改成 `en`(`TestDefaultIsEnglishOnceMigrated` 強制);測試二進位永遠是 zh-TW。`capy config set language zh-TW` 會檢查值在不在支援清單裡,大小寫與底線寬鬆接受(`zh_tw` 也認)。
- `Execute()` 在建命令樹之前讀 config、設定語系。
- 網頁:每個 job 在建命令樹之前重讀,所以網頁切完語系,下一個命令的輸出就是新語言。兩個直達端點(`/api/now`、`/api/isrc`)只讀 atomic 的目前語系,沒有競態。允許清單照舊在 Serve 前建一次;`/api/commands` 的命令清單在 Serve 前每個語系各算一份(Short 與 flag 說明都跟著語系),每次請求照 config 的 `language` 挑,不在 Serve 後重建命令樹、也不在序列槽外 `Set`。
- 互動式介面:它執行的子命令本來就是重新啟動一次 capy,切完立刻生效;介面自己的字(底部提示、選單說明)重開介面後生效。
- config 讀不到或沒設 `language`:用預設、不提示(config 壞掉由真正讀它的命令報;全新使用者不會每次都多一行)。值不認得:用預設,並在那次命令的 stderr 提示一次;網頁印在那個 job 的 stderr。

### 2.4 網頁介面

- 新增 `GET /api/i18n`,回傳目前語系、支援清單與網頁用的那部分目錄(只有 `web.*` 的 key)。JS 用 `t(key, params)`;`index.html` 裡的靜態文字用 `data-i18n` 屬性;`<html lang>` 跟著換。
- 右上角放語言選單。選了就透過一般的命令路徑跑 `config set language <代碼>`,主控台看得到這筆紀錄;成功後重新讀取目錄、重繪整頁。有命令在跑時選單先停用,因為一次只能跑一個命令。
- 解除那五處對中文文字的依賴:
  1. **帳號狀態**:新增 `capy auth status --json`,只輸出各平台「有沒有、何時到期、client 從哪來、email、storefront」,不含任何 token 值。網頁改讀它,腳本也能用。
  2. **逐筆裁決的提示**:提示事件多帶一個穩定的 `key`,就是那句提示的 i18n key,網頁比對 key 而不是文字。
  3. **推不推得過去**:TSV 最後多一欄 `REASON_CODE`,放機器可讀的原因代碼(例如 `no_mapping`、`unpushable`、`dup_id`、`dup_isrc`,代碼表在 T2b 定)。給人看的 `REASON` 跟著語系,腳本與網頁改看 `REASON_CODE`。加在最後一欄,現有欄位的位置都不變。見 Q52。
  4. **表頭**:四張中文表頭改成英文大寫欄名,例如 `NAME`、`TRACKS`、`OWNER`、`TITLE`、`ARTISTS`、`ALBUM`、`DURATION`、`KEY`、`VALUE`,跟 pull / sync 那些表一樣,兩種語言都不翻譯。這四張表在非 TTY 本來就不印表頭,所以只影響終端機與網頁的顯示,不是 TSV 契約變更。網頁照欄名找欄位,表格元件本來就認得 `DURATION`。見 Q51。
  5. **已取消**:用結束事件本來就有的 cancelled 狀態判斷,要藏掉的那句訊息改成跟目錄裡的同一句比對。
  兩個下拉選單改用 `value` 屬性,不再拿顯示文字當值。

### 2.5 讓「漏翻」在 CI 就擋下的測試

- **目錄一致**:每個語系的 key 集合要跟 `en.json` 一樣、每則的佔位符要一樣、複數類別要符合該語言的 CLDR 規則。
- **程式與目錄對得上**:用 `go/ast` 找出所有 `i18n.T` / `Errorf` / `NewError` 的 key,每個都要在 `en.json` 裡;`en.json` 裡沒人用的 key 也要報出來;呼叫時給的佔位符名稱要跟目錄一致。
- **程式碼不准再有使用者看得到的中文**:掃非測試的 Go 檔與網頁的 JS / HTML / CSS 字串,含中日韓字元就失敗。註解不算;開發者工具與測試資料列白名單。遷移期間這份白名單一開始列出所有還沒搬的檔案,每個 PR 縮小一些,最後清空。
- **英文冒煙測試**:用英文跑一組代表性命令,輸出不能有中文,也不能有沒翻到的 key。
- **既有測試照舊有效**:`i18n` 在測試執行時(`testing.Testing()`)預設繁中,一個地方就讓所有套件至少 232 處的中文斷言不必改,也證明搬進目錄的中文一字未改。只有 3 個套件有 `TestMain`,所以不採逐套件設定。英文的測試自己明確切到 `en`。
- **Apple 揭露**:每個語系都要有完整的揭露,`auth login apple` 在兩種語言下都要印出來、不能跳過。

## 3. 對既有約束的影響(CLAUDE.md 在 T1 就改)

- 網頁那條「非 TTY 純文字契約一個位元組不改」**在 T1 就**改寫成:**機器欄位不變**(TSV 欄名、`action` / `dir` 的值、`REASON_CODE`、exit code);**給人看的文字跟著語系**(`REASON` 欄、stderr、說明)。預設改英文後,靠比對中文 stderr 的腳本會失效,要寫進發行說明。
- Apple 揭露:每個語系都必須完整、不可跳過。
- 新增一條硬約束:使用者看得到的字串一律走語系目錄;新增字串時 `en` 與 `zh-TW` 要同時補上。
- 「隱私權政策要跟程式一致」不受影響,除非 Q53 決定調整網站結構。

## 5. 翻譯與新增語系的流程

- **英文由我撰寫**。會先定一份術語表,讓全部訊息用詞一致,例如「正本」「清單」「平台」「資料庫」「對應」「裁決」「閾值」「安全閥」「協作清單」「精選」「喜好歌曲」「已下架」各自固定一個英文詞;術語表放在 `internal/i18n/README.md`,review 時一起看。
- **新增語系的步驟**,寫成文件放在 repo:
  1. 複製 `en.json` 成 `<語言代碼>.json`,例如 `ja.json`。
  2. 翻譯字串;不確定的先留英文,會自動退回英文顯示。
  3. 在支援清單加一行。
  4. 跑 `go test ./internal/i18n/`,缺的 key、錯的佔位符、不符合該語言複數規則的地方都會列出來。
  5. 網頁的語言選單與 `config set language` 會自動出現新語言。

## 6. 風險

| 風險 | 對策 |
|---|---|
| 英文字比較長,互動式介面底部四行、表格、網頁按鈕可能放不下 | 既有的窄終端機測試加一組英文版;網頁在驗收時兩種語言都看 |
| 搬字串時不小心改到中文 | 既有測試用 zh-TW 跑,原本的中文斷言會抓到 |
| 漏翻或 key 打錯 | §2.5 的守門測試 |
| 網頁切語系後,某些已經畫好的區塊沒更新 | 切完整頁重繪;列為驗收項 |
| 既有使用者升級後突然變成英文 | 見 Q54;發行說明寫明怎麼切回中文 |
| `REASON_CODE` 多一欄 | 用 `cut -f` 按位置取欄的腳本不受影響;檢查欄位數、或拿最後一欄當原因的會受影響,寫進發行說明 |

### 決策 50(2026-09-23 定案;已寫進 ARCHITECTURE 附錄 C)

> 多語系:預設英文,config `language`(`en` / `zh-TW`)決定,網頁介面改的是同一個設定。`internal/i18n` 是只依賴標準函式庫與 `x/text` 的葉子套件,語系由 cli 層設定。每個語系一個 JSON 目錄(`en.json` 是來源與模板),語意 key、具名佔位符、CLDR 複數,不加依賴。機器欄位(TSV 欄名、action / dir 值、`REASON_CODE`、exit code、表頭)不翻譯;給人看的文字跟著語系:語系在每個命令建樹之前決定,package 層級的值在印出時才翻。守門測試保證目錄一致、key 都存在、程式碼裡沒有未搬的中文字串。
