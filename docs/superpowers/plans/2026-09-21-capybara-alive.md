# 常駐的水豚(2026-09-21)

使用者看過 PR #72 的開場動畫之後:「希望 CLI 的水豚也能像 web 一樣一直動。」

這件事**推翻 PR #45 的一個決定**(計畫 `2026-09-09-tui-redesign.md` §10:「水豚印一次、之後永不重繪」),所以先寫下來:
當時為什麼那樣定、現在憑什麼可以改、改了之後哪些事不可以再發生。

---

## 1. PR #45 當時修的是什麼

第一版 TUI 把 19 行(其中 8 行是水豚)整塊重繪。使用者看到的是「水豚頭重複三次、歷程完全不可讀」。成因不是
「水豚在畫面裡」,而是這三件事:

| # | 成因 | 機制 |
|---|---|---|
| H1 | 畫面比終端機高 | inline renderer 的游標上移被頂端截斷,舊畫面留在上面,每重繪一次多一份 |
| H2 | 畫面變矮 | bubbletea v2.0.2 + uv 的 `TerminalRenderer` 縮短畫面時只清底部那幾行,上面空出來的列原封不動留在捲動區 |
| H3 | 水豚還在畫面裡就執行子命令,之後又印一次 | 捲動區一隻(或半隻)、畫面一隻 |

`View` 的註解還記了第四件:交出 / 收回終端機(`tea.ExecProcess`)時,renderer 以「畫面的行數 − 1」上移再重畫,
畫面不是一行的話會蓋掉子命令輸出的最後幾行(H4)。

## 2. 決定

| # | 決定 | 對付哪個成因 |
|---|---|---|
| D1 | 終端機至少 `tuiAliveMinHeight`(30)行、而且寬到放得下整隻,水豚才常駐;常駐的畫面固定是 `capyBlockRows`(11)+ 4 = 15 行。不夠大就照舊:開場演一遍、定格印進捲動區、之後永不重繪。還沒收到 `WindowSizeMsg`(高度 0)當作不夠高;尺寸晚一拍到的話畫面從開場的 11 行長成 15 行——是變高,安全 | H1 |
| D2 | 常駐的那一塊**高度固定**。斜線選單打開時借水豚的位置(貼著分隔線、上面補空行;選單最多 8 列,放得下),收起來水豚就回來。常駐時不需要 `menuHigh` 那一套 | H2 |
| D3 | 常駐的水豚**只活在 View 裡、永遠不印進捲動區**。開場的計時器到了、按了鍵,都不定格 | H3 |
| D4 | 子命令執行中畫面照舊縮成一行空白——水豚也讓開。15 → 1 這一下之所以乾淨,是因為命令的回音先 `tea.Println` 進捲動區(推東西進去會把 renderer 的位置重設到畫面頂端,之後縮才清得乾淨;第二輪計畫記過);命令跑完 1 → 15 是變高,沒有問題 | H2、H4 |
| D5 | 視窗縮到放不下:`freeze()`——先把定格幀印進捲動區、畫面才縮成四行(同 D4 的理由)。**單向**:印過就不再常駐,之後視窗再變大也一樣,不然捲動區一隻、畫面一隻 | H1、H2、H3 |
| D6 | 閒著的節奏(`capyIdle`)跟網頁那隻一樣:4 秒眨一次眼、5.5 秒往後撥兩下耳朵,另外每 24 秒吃一根草。一分鐘裡至少四分之三的幀是站著不動的——每 250 毫秒都在動的吉祥物很吵 | — |
| D7 | 一條 ticker、一個計數器:`capybaraFrame(n)` 先照劇本(`capyStory`)演一遍,演完接 `capyIdle`。不另開訊息型別 | — |

**代價**:常駐時捲動區裡沒有那隻橫幅了(複製歷程不會帶到水豚);底部多佔 11 行;ticker 每秒醒來四次(renderer 只寫
有變的格子,站著不動的幀不輸出任何位元組)。**不做**:開關(要的話加一個 config 鍵,一句話的事);一行版的動畫;
`--web` 與非 TTY 完全沒有動到。

## 3. 怎麼驗的

單元測試(`tui_alive_test.go`)守 D1–D5 與 D6 的節奏;五個變異(按鍵會定格、計時器會定格、選單把畫面撐高、縮小不定格、
定格之後又常駐)各自會讓一個測試變紅。

renderer 的行為單元測試量不到,所以用 **pty + 終端機模擬器(pyte)跑真的 binary**(驅動腳本在
`internal/cli/testdata/tui_pty_drive.py`;真帳號只有唯讀的輪詢與 `config list`)。判準:捲動區 + 畫面裡「水豚的腳」
那一行恰好出現一次,子命令的輸出一行不少。

| 情境(100 × 40) | 結果 |
|---|---|
| 開場演完、閒置 30 秒(含一輪吃草) | 一隻;沒有殘留的字元 |
| `/config list` 兩次 | 輸出五行完整、回音與結束碼都在;一隻 |
| `/pl` 開選單 → ` s` 過濾到兩列 → Esc | 高度不變、沒有殘留;Esc 後水豚回來 |
| 連跑六次 `config list` 把畫面塞滿、捲動 | 一隻 |
| 縮成 100 × 20 → 再跑一個命令 → 放大回 100 × 40 | 定格印一次;之後不再常駐;一隻 |
| `?` 鍵位表、不存在的命令(只推東西進捲動區、畫面不縮) | 表與錯誤訊息完整;一隻 |
| 開過選單 → Esc → 縮成 100 × 20 | 定格之後底部正好四行(`freeze()` 把 `menuHigh` 歸零;沒歸零會多八行空白) |
| 一開始就是 100 × 20 | 照舊:開場、定格印進捲動區 |

模擬器的兩個坑(腳本裡已經處理,記下來免得下次再查一遍):pyte 不認得 kitty 鍵盤協定的 `CSI … u`,會把尾巴當文字
印出來;也不認得 CBT(`CSI n Z`,往回跳 tab 停駐點),而 uv 的 renderer 會用它省位元組——不補的話耳朵那兩行
會畫歪、草的穗會多一顆。兩個都是模擬器的問題,真終端機沒有。

**順帶看到、這次不動的**:不常駐的那條路(矮終端機)在畫面貼著螢幕頂端時,定格那一下 renderer 先用換行把螢幕往上
捲、再插入橫幅,開場畫面的頭一兩行會被捲進捲動區。main 上的 binary 也一樣,跟這次的改動無關。
