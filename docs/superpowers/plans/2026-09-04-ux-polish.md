# UX 打磨計畫(2026-09-04):表格對齊、預設 provider、`play` 統一搜尋與挑選器、shell 補全、`now --watch`

> 給執行者:每個 task 都是「先寫會 fail 的測試 → 實作 → 綠 → commit」。gofmt、`go vet ./...`、`go test -race ./...` 全綠才 commit;CI 是 macOS + Windows 矩陣。**非 TTY 純文字輸出是鐵則**(CLAUDE.md):每一個新增或修改的命令都要在 `stdout` 不是終端機時給出確定性的純文字,絕不彈互動元件。

**Goal**:讓 `capy` 有現代 CLI 該有的互動體驗,同時不犧牲可腳本化。維護者實測後的四點需求:表格歪斜與斷行、`play <TAB>` 要能列出播放清單與最近搜尋、`play 歌手` 要能播熱門歌曲、要有播放器畫面、要能設定預設 provider。

**基準**:main `77b72b4`(PR #8 已合併)。Google/Drive(P3 T3+)在這批做完之後再回來(決策 17)。

### Controller 裁定(不再問)

- **R1 `capy play` 無參數維持「恢復播放」**。既有語意、既有測試、腳本可能依賴。維護者說的「按下 tab」是 shell 補全,不是無參數行為。要直接開挑選器用 `capy play --pick`。
- **R2 表格縮減順序寫死、不加參數**:規則:超出終端寬度時,**標題為 `ID` 的欄先縮**(保留頭 8 個字寬 + `…`;`devices` 的 ID 在最後一欄,所以用標題找、不用位置),仍超寬則**從最右欄往左**逐欄截斷,**第一個非 ID 欄(曲名/名稱)最後才縮**。`ui.Table` 簽名不變。
- **R3 `cache.json` 是暫時性的**:`config.Dir()/cache.json`,存各 provider 的播放清單(id/name)與最近 50 筆搜尋/挑選紀錄。不是憑證(不違反 keychain 鐵則)、不是 source of truth(不違反 SQLite 鐵則)。**P3 T6 引入 SQLite 時把它併進去並刪掉這個檔**;P3 計畫要對應加一句。
- **R4 Apple 的播放清單播放在本階段回 `ErrNotSupported`**,訊息指向 `pl show`。`Play` 目前用 catalog 歌曲的 `attributes.url` 轉 `music://`,library 播放清單(`p.xxx`)沒有 catalog URL,`music://music.apple.com/library/playlist/p.xxx` 是否可用**未驗證**——**實作者不得自己發明 URL**。挑選器仍列出 Apple 清單,但標「(Apple 暫不支援清單播放)」。列入驗收。
- **R6 指定類型 = 平台第一筆(實作時修訂)**:`--type track|artist`(或前綴)給定時播該類型的**第一筆**結果,平台排序即決定性——原文「恰一筆才播、多筆歧義」會讓 `capy play --type track X` 在腳本裡幾乎必定 exit 2(搜尋很少剛好一筆),等於沒有可腳本化的替代品;舊的 `capy play X`(播第一筆)語意由 `--type track` / `track:` 承接。`--type playlist` 例外:名稱完全相符,否則子字串命中恰一才播。未指定類型的統一路徑維持嚴格規則,並多加一條 3c「曲名完全相符恰一 → 播」(3d 變成「無清單/藝人候選且曲目恰一」)。
- **R5 exit code 慣例**:`0` 成功、`1` 錯誤、`2` 需要人介入(歧義候選)。用哨兵型別 + `root.go` 加 `SilenceErrors`、`main.go` 判斷型別決定 exit code 與是否印訊息;這正是 P3 T8 要的機制,這裡先落地。

### T1 — 表格對齊與終端寬度

**產出**:`internal/ui/ui.go`、`internal/ui/ui_test.go`。

- 根因:`text/tabwriter` 用 rune 數算欄寬,全形中日韓字算 1、實際佔 2 → 歪斜;且完全沒有終端寬度偵測 → 長列被終端機硬折行。
- TTY 路徑改成自己用 `x/ansi.StringWidth` 量寬、`ansi.Truncate` 截斷(lipgloss 的 `table` 縮欄是等比例,表達不了 R2 的順序,用它反而要先自己截再餵)。**非 TTY 路徑一個位元組都不改**(raw TSV,`cut -f` 契約)。
- 寬度:`term.GetSize(int(os.Stdout.Fd()))` 取欄數;取不到(非 TTY 不會走到、或 CI)用 80。超寬時照 **R2** 縮減,截斷加 `…`,以 `ansi.StringWidth` 量、不用 `len`。
- `Bold` 的註解「不要用在 Table 儲存格」的限制解除(lipgloss table 認識 ANSI);把註解改掉。
- 樣式:標題列粗體、無外框(避免在窄終端機多吃 2 欄)、欄間距 2。不要引入顏色主題——維護者要的是對齊,不是花。

**測試**(全部用 `ansi.StringWidth` 斷言,不用 `len`):
- 含全形字的列(「派對動物」「五月天」)與純 ASCII 列混排,每一列各欄起點相同。
- 寬度 60 時,一列超寬 → 第 0 欄被縮成 `12345678…`、第 1 欄完整;寬度 40 時最右欄先被截。
- 非 TTY:輸出與修改前逐位元組相同(用既有測試的期望值)。
- `Bold` 的儲存格在 TTY 表格裡不影響對齊。

### T5 — `play` 統一解析 + 挑選器 + exit code(R1、R5)

**產出**:`internal/cli/player.go`、`internal/cli/play_resolve.go`(新,純函式)、`internal/cli/root.go`、`cmd/capy/main.go`、對應測試。

**語法**:
```
capy play                          # 恢復播放(R1,不變)
capy play <query...>               # 統一搜尋
capy play --type track|artist|playlist <query...>
capy play artist:<name> | pl:<name> | track:<name>   # 前綴 = --type 的簡寫
capy play --id <track id>          # 不變
capy play --pick                   # 直接開挑選器(TTY 限定;非 TTY 報錯)
```

**解析規則(機械,依序,寫成 table test)**:
1. `--type`/前綴給定 → 只搜該類型;track / artist 播**第一筆**(R6);playlist 名稱完全相符或子字串恰一;零筆 → 錯。
2. 未指定類型:依序取三種候選——**本機快取**的播放清單(名稱子字串)、藝人搜尋(limit 5)、曲目搜尋(limit 5)。(實作是循序兩次 API 呼叫,CLI 夠用,不加 goroutine。)
3. **唯一明確命中**(依序,命中即播;見 R6):
   a. 快取中有播放清單名稱與 query **完全相符**(trim、不分大小寫)→ 播該清單(Apple 依 R4 → 錯誤指向 `pl show`)。
   b. 藝人結果中有名稱完全相符(恰一)→ 播其熱門歌曲。
   c. 曲目結果中有曲名完全相符(恰一)→ 播。
   d. 沒有清單/藝人候選且曲目結果**恰好一筆** → 播。
   e. 否則歧義。
4. 歧義:**TTY** → `huh.Select`(`Filtering(true)`)列出全部候選(清單 / 藝人 / 曲目分組標示,可打字過濾)→ 選了就播;**非 TTY** → exit 2,stdout 印 TSV `type\tid\tlabel\tdetail`,不播、不彈。

**exit code 機制(R5)**:`internal/cli` 定義 `type AmbiguousError struct{ Candidates []candidate }`(實作 `error`);`root.go` 加 `SilenceErrors: true`;`main.go`:`errors.As` 到 `AmbiguousError` → exit 2 且**不印 `Error:`**(候選已印在 stdout);其他 error → 印到 stderr、exit 1。

**輸出**:成功一律一行 `▶ <label>`:曲目 `▶ 派對動物 — 五月天`;藝人 `▶ 五月天 的熱門歌曲(10 首)`;清單 `▶ 清單:通勤(23 首)`。

**測試**(`play_resolve` 純函式 table test,不需網路;cli 層用 `swapProviderWith` 假 provider + `stdinIsTTY` stub):規則 1–4 各一列;`--pick` 非 TTY 報錯;歧義非 TTY exit 2 且 stdout 是 TSV、stderr 無 `Error:`;成功後 `recent` 寫入;無參數仍是 resume(既有測試不可壞)。挑選器本體需要 TTY,用 seam `runPlayPicker` 測分流(同 Spotify 精靈慣例)。

### T6 — shell 補全(決策 14)

**產出**:`internal/cli/completion.go`(新)、`README.md`、對應測試。

- `play` 與 `pl show` 掛 `ValidArgsFunction`:候選 = 快取的播放清單名 + `recent` 的 label;回 `cobra.ShellCompDirectiveNoFileComp`。`--provider`、`--type` 用 `RegisterFlagCompletionFunc` 列合法值。

**測試**:補全函式對假快取回正確候選與 directive;**一個 seam 測試:把 `newProvider` 換成會 `t.Fatal` 的版本,跑補全,證明沒被呼叫**;空快取回空候選不報錯。
