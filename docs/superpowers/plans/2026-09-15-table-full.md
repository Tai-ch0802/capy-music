# 表格資訊完整呈現(2026-09-15)

使用者:「橫向捲軸請幫我立案做調整和開發,我希望表格資訊都可以順利查閱。不要是 `…` 去精簡,
我期望的價值是:資訊要給完整,不要給一半。」定案:**先 W(逐格換行)後 P(分頁器)**,兩個 PR。

---

## 0. 現況

`ui.Table` 在終端機裡先量每欄最寬的儲存格,放不下就 `fitWidths` 縮欄(ID 先縮到 9、再從右往左縮到 4、
曲名最後),縮過的儲存格用 `…` 截斷 —— 118 欄的終端機看 `pl show`,ID 與專輯都被截。
非 TTY 是 TSV,本來就完整,一個位元組都不動。

## 1. W:逐格換行、不截斷(這個 PR)

- 欄寬還是先量自然寬度、放不下才縮;縮過的儲存格**換行**(`ansi.Wrap`:英文在字邊界斷、CJK 逐字斷、
  跳脫碼保留),一列展開成「各欄行數的最大值」行,每行各欄補到欄寬對齊。表頭跟資料列一視同仁:
  欄名比縮過的欄寬長也會折(`PROVIDER_ID` 在 80 欄折成 `PROVIDER` / `_ID`)。
- **原子欄不縮**:`ID`、`*_ID`、`CID`、`PID`、`ISRC`、`DEVICE`(靠標題名判斷,規則集中在 `ui.atomicHeader`)——
  它們是要複製去下一個命令的字串,折成三段夾在補白裡比看得出被截的 `…` 更糟(review #51)。
  縮的順序:最右欄往左,名字欄(`曲名` / `名稱` / `TITLE` / `NAME`,沒有就第一個非原子欄)最後;下限從 4
  提到 12(一行放得下一個短單字),還放不下再以 8 縮一輪;還是放不下就**盡力而為**(留著縮過的欄寬,
  超出的交給終端機折行)——全部還原成自然寬度會讓差幾欄變成差幾十欄(review #51)。
- **已知的極限**:9–10 欄又帶 22 字 Spotify ID 的 `pl pull` / `pl sync` / `resolve` 表,在 80 欄終端機
  怎麼縮都放不下(原子欄就佔了 34 欄),會超寬幾十欄交給終端機軟折行;118 欄放得下。這幾張表正是
  分頁器(P)要救的。
- 效果:資訊永遠完整,留在捲動區、可往回捲、可複製;介面裡 / 介面外一樣。
- 代價:窄終端機下列會變高(80 欄 + Spotify 22 字 ID:曲名 22、藝人 / 專輯 12);使用者的 118 欄大多一列一行,
  最長的專輯名折成兩行。
- 測試:每一行寬 ≤ 終端寬(獨立的尺)、沒有 `…`、ID 完整、每欄的碎片接回去等於原文(去空白比)、
  非 TTY 逐位元不變、放不下時放棄而不是截。
- README / 指南補一句「放不下就換行、不截斷,ID 永遠完整」。

## 2. P:檢視窗格(第二個 PR)

- 表格比終端機寬、而且 stdin / stdout 都是 TTY 時,子命令自己開 alt-screen 的 viewport(bubbles v2 的
  viewport 內建橫向捲動),整張表以自然寬度排、每列一行;←/→(h/l)橫向一次 8 欄、↑/↓(j/k)上下、
  PgUp/PgDn、g/G 到頭尾、q / Esc / Ctrl-C 離開;表頭固定在最上面、跟著橫向捲;底部一行
  「第 1–24 列 / 33 · 欄 1–118 / 236 · ←→ 橫向 ↑↓ 上下 q 離開」當捲軸(不畫圖形捲軸:方框字元在 CJK
  終端機寬度不對)。子命令拿到的是真的 TTY,介面裡也能用,不需要 pty + VT 模擬器。
- 離開之後把 W 的換行版印進捲動區當紀錄:窗格關了就沒了,紀錄要留在可回捲、可複製的地方。
- 放得下、非 TTY、stdin 是管線(cron 把 stdout 接到終端機那種)、沒有列:都不開,行為同 W。
- 窗格開不起來(bubbletea 回錯)就直接印換行版,不擋輸出。
- 測試:窗格的 Update / View 是純函式(捲動、夾住、狀態列、表頭跟著捲、離開鍵);`Table` 的開關條件用
  `Pager` / `StdinIsTTY` 兩個替換點驗。
- 代價:多一個要離開的畫面;「放得下不開、放不下才開」兩種體驗。
- 待決(review #51 提的):W 的多行列之間要不要分隔(只在有換行的列後面空一行)。`pl show` / `pl list` 有 ID
  當錨點;會展開成 3–4 行的是 pull / sync / resolve,它們在 80 欄本來就是 P 的守備範圍,P 做完再看。

## 3. 產出
- W:`feat/table-wrap`,一個 PR。
- P:另一個 PR,W 合併後開。
