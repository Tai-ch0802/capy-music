# 表格資訊完整呈現(2026-09-15)

使用者:「橫向捲軸請幫我立案做調整和開發,我希望表格資訊都可以順利查閱。不要是 `…` 去精簡,
我期望的價值是:資訊要給完整,不要給一半。」定案:**先 W(逐格換行)後 P(分頁器)**,兩個 PR。

---

## 0. 現況

`ui.Table` 在終端機裡先量每欄最寬的儲存格,放不下就 `fitWidths` 縮欄(ID 先縮到 9、再從右往左縮到 4、
曲名最後),縮過的儲存格用 `…` 截斷 —— 118 欄的終端機看 `pl show`,ID 與專輯都被截。
非 TTY 是 TSV,本來就完整,一個位元組都不動。

## 1. W:逐格換行、不截斷(這個 PR)

- 欄寬還是先量自然寬度、放不下才縮;縮過的儲存格**換行**(`ansi.Wrap`:英文在字邊界斷、CJK 逐字斷、
  跳脫碼保留),一列展開成「各欄行數的最大值」行,每行各欄補到欄寬對齊。表頭不換行(欄名短於下限)。
- **ID 欄不縮**:ID 是要複製去下一個命令的原子字串,斷成兩行沒意義。縮的順序照舊(最右欄往左、第一個
  非 ID 欄最後),下限從 4 提到 12(一行放得下一個短單字);還放不下就再以 8 為下限縮一輪;還是放不下
  就放棄、讓終端機自己折行(和現在一樣)。
- 效果:資訊永遠完整,留在捲動區、可往回捲、可複製;介面裡 / 介面外一樣。
- 代價:窄終端機下列會變高(80 欄 + Spotify 22 字 ID:曲名 22、藝人 / 專輯 12);使用者的 118 欄大多一列一行,
  最長的專輯名折成兩行。
- 測試:每一行寬 ≤ 終端寬(獨立的尺)、沒有 `…`、ID 完整、每欄的碎片接回去等於原文(去空白比)、
  非 TTY 逐位元不變、放不下時放棄而不是截。
- README / 指南補一句「放不下就換行、不截斷,ID 永遠完整」。

## 2. P:分頁器(下一個 PR)

- 表格比終端機寬時,子命令自己開 alt-screen 的 viewport(bubbletea),整張表以自然寬度排、每列一行;
  ←/→ 橫向、↑/↓ PgUp/PgDn 上下、q / Esc 離開;底部一行「第 1–24 列 / 33 · 欄 1–118 / 236」當捲軸
  (不畫圖形捲軸:方框字元在 CJK 終端機寬度不對)。子命令拿到的是真的 TTY,介面裡也能用,不需要
  pty + VT 模擬器。
- 離開之後捲動區留什麼(只留一行摘要 / 留 W 的換行版)到時候再定。
- 代價:多一個要離開的畫面;「放得下不開、放不下才開」兩種體驗。

## 3. 產出
- W:`feat/table-wrap`,一個 PR。
- P:另一個 PR,W 合併後開。
