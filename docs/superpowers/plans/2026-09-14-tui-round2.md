## 2. 修法

### A. 選單:Tab 補齊;`/` 後面是完整命令就直接執行

- 選單開著時 Tab 與 ⏎ 都是「把選中的命令帶進輸入行」(結果不帶 `/`)。
- 選單只在「`/` 後那段還不是完整命令」時開著(`tuiIsCommand`:字詞比對,剛好等於某個命令路徑、或命令路徑後接參數)。
  `/pl show 冬日暖調`、`/pl list` 都算完整 → 選單收起、提示列變「Enter 執行」→ ⏎ 執行去掉 `/` 的那行。
  使用者在兩個選項裡選了這個((b) 直接執行),而不是「帶進輸入行、再按一次 ⏎」。
- 命令自己可執行、底下又掛子命令(`resolve` / `resolve pin`):`/resolve p` 算「還在打 `resolve pin`」,選單留著;
  `/resolve pin` 剛好是命令、`/resolve x` 沒有命令接得下去,才執行(PR #47 review 抓過 `resolve pin` 被丟掉)。
- 選單開著但比不到任何命令:⏎ 照打的執行,由 cobra 報 unknown command——`/` 永遠不再吞掉 ⏎。
- 只有 `/`:⏎ / Tab 帶第一個命令進輸入行;**永遠不會執行不帶參數的 capy**(那會再開一層介面)。
- 歷史與回音都存去掉 `/` 的那行。提示列、`?` 鍵位表、README、使用指南同步改字。

### B. 子命令執行中,底部區縮成一行空白

- ⏎ 執行時 `running = true`,View 只回一行空白;`tuiExecMsg` 回來恢復四行。
- 為什麼有效:bubbletea 交出終端機前把游標移到畫面最後一行再清到底 —— 一行的話整個清掉,子命令輸出從回音的
  下一行開始;收回時它上移「行數-1」= 0 行再重畫,底部區從游標所在處(子命令輸出的下一行)往下畫,不再蓋掉三行。
- 回音前多印一個空行(`"\n" + 回音`;`tea.Println("")` 會被 insertAbove 當空字串跳過)。使用者在「空行」與
  「橫線」之間選了空行。
- 子命令期間 event loop 是擋住的,排隊的輪詢訊息會先於 `tuiExecMsg` 進來:那時 View 仍是一行,畫在同一個位置,
  不會蓋到輸出。
- 前提:子命令的輸出以換行結尾(capy 的命令都是)。

### B′. 底部區的高度到下一個命令之前只長不縮

驗證 B 時撞到另一個現行版本就有的殘留:bubbletea 的 inline renderer(uv `TerminalRenderer`)縮短畫面時,
先把游標列夾進新高度再「移到頂端、清到底」,所以只清底部那幾行,上面空出來的列原封不動留在捲動區。
打 `/pl s` 把選單從八列過濾到兩列,舊的六列疊在選單上方;選單收起(Tab / 打到完整命令 / Esc)也一樣,
舊的選單列最後疊在下一個回音上方,永久留在捲動區。A 讓「打完整命令 → 選單收起」變成主要路徑,
這個殘留會更常出現,所以一起修。

- View 補空行撐到這一輪選單佔過的最高點(`menuHigh`),空行在選單上方、選單貼著分隔線;
  變短或收起都不縮,離開輸入也不縮(縮了就留一排空行在捲動區)。
- 推東西進捲動區時歸零:insertAbove 會把 renderer 的位置重設到畫面頂端,接著那次縮的 `ESC[J` 才會把
  整塊撐高的區域一起清掉。命令回音、`?` 鍵位表、`printErr` 都算(review 建議從「命令執行時」放寬)。
- 代價:開過選單又沒跑命令(Esc 出來)時,分隔線上方會留一塊空白到下一次推東西進捲動區為止 —— 在畫面裡、
  不進捲動區。
- 順手修的:`?` 的鍵位表原本被 `tuiJoin` 的單行預算截成三行(`tuiWidth` 把換行算 0 欄,量到所有行的加總;
  main 就這樣),改成逐行夾寬度(`printBlock`),這次新加的選單說明才印得出來。
- 沒選的做法:選單改往下長 + 用真的游標(游標停在輸入行,縮短時不會被夾)可以每一步都乾淨,但輸入行會
  隨選單開合上下跳,而且推翻 §2.3 的設計;先用補空行。

### C. 不做:橫向 / 上下捲軸

- 上下:A、B 修完後表格不再少行,終端機自己的捲動(滾輪、Shift+PageUp)就是上下捲。
- 橫向做不到「小修」:子命令是真的行程、直接畫在終端機上(挑選器與確認提示能運作的前提)。要橫向捲得把子命令
  跑在 pty 裡、在介面內用 VT 模擬器把輸出畫進可捲動的窗格——等於做一個 tmux 窗格。A、B 上線後由使用者決定
  要不要另外立案。

## 4. 驗證邊界與驗收

- pyte 不是真的終端機,而且 bubbletea 在 Windows 上關掉 scroll optimization,模擬器只驗了 macOS 這一型的
  輸出。驗收:`capy update --dev` 之後在真的終端機連跑兩次 `config list`,五行都在、兩段之間有空行、沒有
  殘留的三行;Windows 未驗。
