> **這份文件是交接用的單一入口。** 先讀 §0 與 §1,再照 §3 執行。視覺規格在同日的 [2026-09-18-web-consumer-design.md](2026-09-18-web-consumer-design.md);它**取代** [2026-09-17-web-mode-design.md](2026-09-17-web-mode-design.md) 裡與它衝突的條文(哪些留、哪些退役,見那份的 §2)。
> 撰寫日期 2026-09-18。基準 commit:main `19e04f3`(執行狀態列與中止 PR #65 已合併)。
> **T0 不是 gate**(沿用決策 44 與使用者 2026-09-17 的指示):計畫 PR 開出來就接著做 T1;每個 T 各自開 PR、各自走 review 循環,CI 三個 check 都 SUCCESS 才合併。

使用者原話(2026-09-18):「我覺得現在介面有點太工程師了。既然已經做成 web,我希望可以更面向大眾使用者。除了保留既有的各項功能以外,我希望你可以參考這網站的介面。https://www.tunemymusic.com/transfer/apple-music-to-spotify 他讓使用者可以一目瞭然知道我該如何轉換我的 play list。雖然做法細節有些不一樣,但我希望你可以用一些更生動的動畫、示意圖,來讓使用者知道我們的工具會如何幫助使用者進行播放清單的搬遷,這是很重要的吸引用戶的功能之一,因為以往其他平台都需要付費,但我們不用。我們主打開源、免費。」

參考站讀到的結構(2026-09-18 實際開過;只取結構,不抄文案與素材):開場是「來源圖示 → 目的地圖示」+ 一句話 + 一顆大按鈕;下面三步說明(連接帳號 → 選要搬什麼 → 配對並重建,進度條隨每一首填滿)、完成報告(沒搬到的歌列出來、可下載)、這條路線的注意事項、其他功能一覽。深色底。

## §0 現況(2026-09-18)

- `capy --web` 七頁(主控台 / 搜尋 / 播放清單 / 同步 / ISRC / 帳號 / 診斷)+ dock(播放列、執行狀態列、命令列)。預設落在主控台;每頁標題旁是 CLI 等價命令;同步頁的按鈕叫 `pull / push / sync / dedup / migrate`;配色是 GitHub 深色 + mono 字 + 全直角 + 掃描線。**功能齊,但第一眼是終端機。**
- 搬清單的能力已經有了:`capy migrate <來源清單 ID 或名稱> --from <平台> --to <平台>[:<既有清單>]`(決策 39;`internal/cli/migrate.go`)。參數給齊時不開挑選器;一張表、一次確認;確認之後才在目標建清單;永遠不動來源、對目標只新增、順序不動(決策 38)。web 端的確認與逐筆裁決經提示橋(決策 40)。
- 資料來源都現成,全部走 `Console.run`(單一序列槽):連線狀態 = `auth status`(`account.js` 的 `parseStatus` / `stateOf`)、來源清單 = `pl list --provider X` 的 table 事件(ID / 名稱 / 曲數)、預覽與報告 = `migrate` 的 table 事件(`dir action provider playlist pos cid provider_id title artists reason`)。
- **沒有的**:每一首的進度。`planResolve` 逐首反查(最久的一段)與 `applyPlans` 都不印逐筆輸出,SSE 也沒有進度事件(#65 的結論:不編百分比)。
- 提示目前畫在主控台的區塊裡,從別頁發起時自動切到主控台(#64)。對精靈來說,這等於做到一半把人丟進終端機。
- 平台現實(不會因為換皮而改變,精靈必須照實說):三個平台、其中 Apple 只讀(不能當目的地,gate R-8 未過);只有 Spotify 能新建清單,本機曲庫只能加進既有的 M3U;憑證全面 BYO(Spotify 要自建 app、Apple 要自己從網頁播放器複製 token 且揭露不可跳過、Google 登入才有 Drive 正本)。**「連接帳號」不可能像參考站那樣一鍵 OAuth,精靈要引導,不能假裝。**

## §1 本次拍板的決策(附錄 C 決策 45–48)

### 決策 45:面向一般使用者 —— 首頁是搬家精靈,終端機退到「進階」

- 預設路由改成 `#/move`(搬家)。導覽兩層:**搬家 / 我的清單 / 同步 / 搜尋 / 帳號**,以及收合在「進階」底下的 **主控台 / ISRC 查詢 / 診斷**。八頁,鍵位 1–8。既有功能一個不少。
- 每一頁的第一眼不出現命令字串:標題旁的 CLI 等價命令拿掉,按鈕改成說人話的動作(同步頁的 `pull / push / sync / dedup` → 「從平台更新 / 推到平台 / 雙向同步 / 去除重複」)。命令原文仍然看得到:執行狀態列點了到主控台,主控台照舊一命令一區塊。
- 命令列只在主控台頁出現(`/` 先切到主控台再聚焦)。播放列與執行狀態列七頁都在。執行狀態列顯示頁面給的白話標籤(「正在讀取你的播放清單」),沒給才顯示命令原文。
- 主視覺:**保留**深色、唯一主色 GeekGreen `#3FB27F`、水豚;**退役** mono 內文、全直角、掃描線、「霓虹預算」與 GitHub 灰藍底。理由與完整規格見設計文件。主控台頁保留終端機樣貌(它就是終端機)。淺色主題不做(Q38)。

### 決策 46:搬家精靈的形狀 —— 只組命令,確認照 CLI,提示就地回答

- 三步:**① 選路線**(來源與目的地;每個平台顯示連線狀態,沒連的給「連接」鈕走既有的 `auth login <平台>`)→ **② 選清單**(來源平台的清單;目的地選「建一個同名的新清單」或既有清單)→ **③ 確認並搬家**。
- ③ 只跑一次 `migrate <來源清單 ID> --from X --to Y[:<目標 ID>]`:用 ID 不用名字(同名清單不會歧義);table 事件 = 預覽,CLI 自己的確認提示 = 「開始搬家」。**頁面絕不代加 `--yes` / `--force`,也不自動回答確認**(同 `sync.js` 的規矩)。取消 = exit 2、零寫入、清單也沒建。
- 提示(確認、逐筆裁決、登入精靈、Apple 揭露、授權連結)在精靈裡就地渲染:`Console.run` 多一個選項把提示畫進呼叫端給的容器,不切到主控台。Apple 揭露照舊不可收合、不可跳過。
- 照實呈現限制:Apple 當目的地是灰的並寫明「目前只能從 Apple Music 搬出來」;本機曲庫當目的地只列既有的 M3U;目的地已有同名清單時 CLI 會擋,精靈把那句話翻成「加進它」的選項。
- 完成報告:搬了幾首、沒搬到的歌逐首列出(來源 = table 裡 `skip` 的列與原因)、下一步(想持續同步 → 同步頁)。
- 一次搬一個清單。多選排隊是 Q39。

### 決策 47:裝飾動畫與真實進度分開 —— 進度要有資料來源

- **示意動畫**(首頁的「來源 → 水豚 → 目的地」與三步說明)是裝飾:可以循環,`prefers-reduced-motion` 下是靜態構圖。它只在沒有命令在跑時出現在主視覺位置。
- **真實進度**只由伺服器事件驅動:新增 `progress` SSE 事件(`stage` / `done` / `total`)。Go 端是一個 package var 接縫(預設 no-op,`installWebSeams` 換成送事件),`planResolve` 每反查一首、`migrate` / `applyPlans` 的每個里程碑各叫一次。**終端機與非 TTY 輸出一個位元組不改。** 有了它,比對階段才畫得出「37 / 120」;在那之前(T2)只顯示階段文字與計時,不畫假的進度條(#65 的規矩)。

### 決策 48:不用官方標誌;主打的話要是真的

- 平台一律用文字 chip(Apple Music / Spotify / 本機曲庫)加單色字符,不內嵌 Apple / Spotify 的官方 logo(兩家的品牌規範都有條件,開源專案內嵌是商標風險)。水豚是我們自己的。
- 首頁的主張只寫查得到的事實:免費、開源(MIT)、在你自己的電腦上執行、帳號憑證只進作業系統的鑰匙圈、清單正本在你自己的 Google Drive、不刪來源只新增、順序不動、沒有曲數上限。不寫「支援所有平台」,不點名競品,不寫「一鍵」。
- 本機 M3U → Spotify 是真的差異點(別家多半要付費才收檔案),照實主打。

## §3 任務切分(每個 task 一個 PR)

### T0 — 本計畫 + 視覺規格 v2 + ARCHITECTURE(docs only;分支 `feat/web-consumer-plan`)

### T1 — 視覺系統與外殼(分支 `feat/web-consumer-shell`)
`tokens.css` 換色票 / 圓角 / 字級 / 動效 token;`app.css` 跟進;導覽兩層 + 八頁路由(`#/move` 先放一個誠實的佔位:一句話 + 「到同步頁用 migrate」的連結,T2 換掉);命令列只在主控台頁;各頁按鈕與空白態改白話、標題旁的 CLI 命令拿掉;`Console.run` 的 `label` 選項。
測試:`TestWebStaticFrontendContracts` 逐條處理——安全與無障礙的照留(IME、role=status、no aria-live、CSP 零 inline、secret 遮罩、z-index 走 token、reduced-motion);「glow 只准在 budget 註解塊」「掃描線」這類隨規格退役的,**刪掉並在測試註解寫明被哪一條新規格取代**,不是放寬到會過;新增:預設路由是 move、命令列在非主控台頁 hidden、八頁鍵位表一致。`TestWebConsoleBehaviour` 加 label 情境。瀏覽器 smoke 八頁 + 400px。

### T2 — 搬家精靈 + 示意動畫(分支 `feat/web-move-wizard`;依賴 T1)
`js/pages/move.js`;`Console.run` 的提示容器選項(提示就地渲染、不 reveal;`focusPrompt` / `promptClosed` 跟著容器走);首頁示意動畫與三步說明(純 CSS `transform` / `opacity`);完成報告。
測試:node 行為測試加情境(提示進容器、不切頁;取消 → onExit 拿到 exit 2;沒有 `--yes`);靜態契約釘「move.js 組出來的命令不含 --yes / --force」「Apple 目的地 disabled」;Go 端既有的 migrate e2e(假平台)不動。**真帳號只跑到預覽(會停在確認提示,按取消),不按確認。**

### T3 — 真實進度(分支 `feat/web-progress`;可與 T2 平行,T2 先合)
Go:`progress` 接縫 + SSE 事件;`planResolve` 與 migrate 里程碑呼叫。前端:`hooks.onProgress`、執行狀態列顯示 `n / total`、精靈的進度條改吃它。
測試:假平台 e2e 斷言事件順序與 `done == total`;非 TTY 輸出 golden 不變(既有測試);node 行為測試加 onProgress。

### T4 — 文件(分支 `docs/web-consumer`)
README 與 guide.html 的網頁介面段改寫(搬家精靈、開源免費、BYO 的實話)、ARCHITECTURE §9 P8 結論、指南重發 Artifact。

## §5 已知風險
